# Ranked roadmap: six highest-leverage new capabilities

## 1. Counterfactual candidate generation and self-improving selection
**Pitch:** Replace blind re-rolls with named prompt variants, auto-rank them, and feed each failure's specific diagnosis into the next generation.
**Why it matters:** `--n 3` currently sends the SAME request body three times (`video-engine.mjs:293,337`) — three samples of the same average, which violates the repo's own rule to vary named dimensions instead of blind re-rolling (`CLAUDE.md:25`). The critic already returns a `weakest` field meant to drive revision, but the engine never consumes it (`CLAUDE.md:230`).
**Effort:** M · **Risk:** optimizing toward critic quirks not operator preference (keep human verdict authoritative). · **Measure:** more survivors per 3 paid gens, lower cost per approved second, beat same-prompt re-rolls in a blind A/B on ≥70% of briefs.

## 2. Executable law graph and conflict-aware brief compiler
**Pitch:** Compile every brief against the measured law graph at runtime, with scoped precedence and a citation trail for every routing/prompt/post decision.
**Why it matters:** The header says it reads `house_laws`/`seedance25_laws`, but it actually hardcodes only duration/cadence/ratio/shot bands (`video-engine.mjs:10,75`); lint can silently skip whole law sections (`seedance25_laws.json:2`). Rules intentionally conflict — house UGC forbids captions (`house_laws.json:95`), campaign requires sound-off captions (`creative_laws.json:148`).
**Effort:** M · **Risk:** weak small-sample laws becoming hard blockers (warn until promoted). · **Measure:** all law sections load+lint; every request has a machine-readable decision trace; golden suite has zero unresolved contradictions.

## 3. Constraint-based Nano Banana × Veo × Seedance router
**Pitch:** Turn the ByteDance-only entry point into a stack-level planner that picks the cheapest backend satisfying identity/duration/resolution/first-frame/audio/product constraints.
**Why it matters:** The route table terminates entirely in Seedance/ModelArk (`video-engine.mjs:55,155`), leaving Veo's reference-identity lock + native audio (`CLAUDE.md:134`), Veo extensions to ~148s (`CLAUDE.md:179`), Seedance 2.0's true 4K for non-humans vs 2.5's 720p cap (`seedance25_laws.json:13,21`) all outside the engine.
**Effort:** L · **Risk:** backend behavior/pricing drift makes stale routing worse than manual. · **Measure:** on a fixed benchmark, higher operator acceptance per dollar; zero requests sent to a backend that can't satisfy a declared constraint.

## 4. Semantic asset preflight and temporal fidelity gate
**Pitch:** Inspect inputs before spending and sampled video frames afterward for identity/product/text/geometry/continuity — not just file health.
**Why it matters:** Input safety trusts author booleans like `contains_person` (`video-engine.mjs:103`); output gating checks transcript tokens + arithmetic watcher (`video-engine.mjs:372`) but never compares against canonical faces/products/artwork. Four clips already shipped off-size because first-frame geometry propagated (`house_laws.json:63`), and first-frame ratio dominance is a hard law (`seedance25_laws.json:29`).
**Effort:** L · **Risk:** false semantic rejections waste good paid outputs (report confidence, reject only on calibrated high-precision fails). · **Measure:** catch 100% of known off-size/privacy fixtures pre-submit; ≥95% precision on identity/product rejection; −50% post-delivery defects.

## 5. Lane-aware campaign assembler and finishing system
**Pitch:** Turn generated beats into a finished spot — shot ladder, cut timing, captions, CTA plate, color match, loudness, delivery variants — while preserving the opposite UGC rules.
**Why it matters:** Finishing today is only loudnorm + 720→1080 conform (`video-engine.mjs:446`). Campaign work is measured to need establish/detail/reaction/hero coverage (`creative_laws.json:132`), ~4.3s cut rhythm (`creative_laws.json:140`), sound-off captions, unified grade, brand-locked CTA (`creative_laws.json:148,156,164`); b-roll is measured 24.5 dB below dialogue (`house_laws.json:55`).
**Effort:** L · **Risk:** formulaic edits flatten pacing (treat 4.3s as a distribution, not a metronome). · **Measure:** pass lane structural checks; full sound-off comprehension in review; within target LUFS; −60% manual finishing time.

## 6. Seedance 2.5 multimodal control surface with automated capability probes
**Pitch:** Add first/last-frame control, motion refs, audio refs, extension, video editing, clay-render — promoting each only after a one-variable endpoint probe passes.
**Why it matters:** The request builder supports ref images + one ref video but no ref audio/last-frame/editing/extension/per-modality authority (`video-engine.mjs:207,237`); Seedance declares those roles/task types but they're untested here (`seedance25_laws.json:133,253,221`).
**Effort:** L · **Risk:** several controls are documented-not-measured, may be app-only or differently shaped on this endpoint. · **Measure:** each enabled control has a reproducible passing probe; motion-ref beats text-only on action/camera similarity; extensions pass continuity with no identity/voice seam.

## Build first
**#1 — counterfactual candidate generation + self-improving selection.** Closes the most expensive gap with the least new infra: the engine already generates candidates, records results, runs gates, and collects verdicts — it just spends the extra generations on identical prompts. Turning each paid candidate into a controlled experiment lifts approval rate immediately, produces cleaner law-graph evidence, and builds the benchmark data the later router needs.
