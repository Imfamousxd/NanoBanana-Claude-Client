# Project audit — 2026-07-22

## Outcome

The repository contained excellent campaign-specific learning but did not yet function as a shared
pipeline. At review time it had approximately 1,790 root entries, 1,158 tracked paths, 495 root-level
`.mjs` scripts, 70 Python utilities, 10 shell scripts, and a 1,117-line `.gitignore`. There was no
shared source/provider layer, versioned job schema, prompt compiler, knowledge retrieval API, test
suite, manifest format, or automated asset/preflight gate. Even read-only `git status` exceeded 90
seconds on the archive-backed filesystem.

Content Engine v2 now provides those missing layers while leaving historical jobs in place.

## Findings in priority order

### 1. One-off scripts were the architecture

Hundreds of jobs repeated `.env` parsing, direct `fetch`, base64 encoding, polling, error handling,
timestamping, output writing, and prompts. Fixes such as retry policy, a model rename, operation
recovery, or secret redaction therefore required editing many files and were rarely applied
consistently.

The reusable root CLIs themselves had weak contracts: unvalidated batch JSON, broad catch-and-
continue behavior that could exit successfully after failures, no timeouts, no bounded poll deadline,
no response provenance, no dry plan, and no static compliance check.

### 2. Active Gemini image routing was expired

`nanobanana.mjs`, `README.md`, `CLAUDE.md`, and the engine guide named
`gemini-3-pro-image-preview`. Google lists that preview as shut down June 25, 2026. The active stable
model is `gemini-3-pro-image`. The legacy CLI and active docs now use the stable model with an
environment override; the v2 adapter also defaults to it.

Google's current video overview now recommends Gemini Omni Flash as the default generation route and
Veo 3.1 when last-frame, extension, or legacy controls are required. V2 therefore exposes both:
`google-omni-video` for current multimodal generation and `google-veo` for Veo-specific control. The
Veo REST image envelope was also corrected to the current `inlineData` schema.

### 3. Knowledge was rich but not executable

`Brand Context/` and the new influencer-persona strategy contain extensive visual rules, asset maps,
prompt language, market assumptions, and compliance guidance. Agents had to load monolithic files and
decide which sentences were current/canonical. There was no entity/relationship map, chunk
provenance, source confidence, or claim expiry.

The hybrid graph/index now separates exact brand/provider/compliance/asset relationships from ranked
Markdown context. A claim-record schema prevents `[S]`, `[M]`, filenames, or generated documents from
masquerading as approved evidence.

### 4. Prompt guidance rewarded repetition more than diagnosis

The old global rule was "one self-contained script per job," which institutionalized duplication.
Prompts held brand rules, provider tricks, negative terms, safety-filter workarounds, composition,
camera, and copy in one block. Iterations frequently became new `v2`–`v29` scripts without a run
manifest stating the failure hypothesis.

The new job/compiler makes invariants, variables, reference roles, exact copy, and timed video beats
explicit. The UGC playbook replaces generic cinematic language with human reason-to-record,
observable performance, ordinary environment facts, causally correct phone capture, product contact,
sound, and platform pacing.

### 5. Paid long-running jobs were fragile

Veo stored one global `veo_operation.txt`, so concurrent jobs could overwrite each other. Replicate
poll loops had no deadline, retry policy, or durable state before polling. Downloads were not checked
uniformly. Batch generation had no resumable per-candidate manifest.

V2 persists one operation/prediction record per job and candidate, uses bounded polling and retry,
and writes a planned manifest before making a billable call. `execution.approved` is a mechanical
cost gate.

### 6. Asset truth was implicit

Reference selection depended on hunting through large campaign folders and trusting words such as
`FINAL`, `Approved`, or `v6`. Asset roles were not machine-readable, series geometry was not checked,
and files could carry the wrong encoding for their extension.

In the targeted recent NuLumin audit:

- The 23 `NuLumin Transparent One-Per-Peptide` exports were unique, structurally consistent PNGs at
  1024×1536.
- `NuLumin Influencer Box/Final/NuLumin_Box_Closed_Hero.png` is actually a 3712×4608 JPEG despite its
  `.png` name. This can break MIME-sensitive provider calls and is now reported at preflight.
- The five satisfying-ad start frames are visually polished, but the sand concept contains two vials
  while the series brief describes one hero, and several small label/footer regions are not reliable
  enough to serve as factual product copy. The directory audit found that all eight generated
  1536×2752 start frames are JPEG-encoded despite `.png` names; only the 1572×591 contact sheet is a
  true PNG.
- `NuLumin_Box_Adam_and_Eve.png` visibly contains invented/garbled microcopy, certification-like
  marks, and a synthetic COA. It must not be used as evidence or a canonical text reference.
- The 23-SKU contact sheet reveals normal generative drift in vial scale, cap proportions, powder
  level, side-label exposure, and typography. Those files may be useful art assets, but the series
  needs per-SKU canonical references plus measured geometry/text review before packaging use.

This visual review was a representative targeted audit, not a claim that every historical bitmap was
manually inspected. The new `assets audit` command makes directory-level structural review
repeatable; semantic text/product review still needs multimodal and human inspection.

### 7. Regulated creator strategy needed evidence gates

The influencer-persona system contains thoughtful separation of sourced `[S]` and modeled `[M]`
figures, plus useful no-use/no-dose constraints. However, bracket markers are not citations an agent
can verify. It also contains rapidly changing platform, regulatory, price, and market claims.

V2 treats the document as strategy context, not an automatic claim bank. Research-use-only creative
blocks human-use, protocols, outcomes, disease claims, and unsupported testing/purity/origin claims;
it requires the exact RUO disclosure, approved claim records, and human review. This is a conservative
engineering control, not legal advice.

### 8. Agent instructions drifted across surfaces

The repository only had a long `CLAUDE.md`, so Codex and other agents had no canonical contract.
Provider examples and volatile model facts lived inside agent instructions. The new `AGENTS.md` is a
lean provider-neutral workflow; `CLAUDE.md` imports it. Brand knowledge stays in the graph/source
documents, and provider volatility stays behind adapters.

## Implemented controls

- Universal agent contract and concise Claude entry point
- Versioned content-job and claim-record schemas
- Graph entities/edges plus provenance-preserving Markdown retrieval
- UGC and general prompt compilation
- Current provider adapters for OpenAI Image, Gemini Image, Gemini Omni Flash, Veo, and Seedance
- Timeouts, bounded retry/backoff, durable operation IDs, secret redaction
- Asset magic-byte/dimension/hash audit and workspace path containment
- Regulated-content, exact-copy, reference, provider, cost, and deterministic-type gates
- Pre-call and final run manifests with SHA-256 provenance
- Optional structured multimodal creative critic plus mandatory human ownership
- Focused Node test discovery and offline unit tests
- Explicit repository migration plan instead of a risky bulk move

## Verification performed

- `npm run check`: 14 offline tests passed, including retry safety, provider constraints, knowledge
  cache invalidation, retrieval, prompt compilation, regulated-content gates, and claim evidence.
- Syntax validation passed for every module under `engine/`; all edited schemas/examples parse.
- `npm run doctor`: Node, credentials, ffmpeg, schema, and the 18-node/12-edge graph validated.
- `npm run knowledge:build`: 289 provenance-preserving chunks built from 19 configured sources.
- A real NuLumin UGC plan completed end to end and surfaced the expected disclosure and MIME
  warnings while retrieving relevant brand/persona/playbook context.
- The package lock was refreshed offline with install scripts disabled; the audit reported zero
  known dependency vulnerabilities.
- No paid image, video, or visual-review request was executed during this refactor.

## Remaining high-value work

1. Build a small golden evaluation set: 10–20 accepted/rejected outputs per major mode/brand with
   reviewer reasons. Use it to compare providers, models, prompts, seeds, latency, and cost.
2. Create verified canonical asset records per product/character with measured crop, geometry, exact
   copy, and usage rights. Normalize misleading extensions without overwriting originals.
3. Populate claim records with owner-approved sources and expiry dates; none are approved by default.
4. Add deterministic overlay/render modules for type, QR, disclosures, COAs, price tables, and CTA.
5. Add video frame sampling plus continuity/identity/label checks and audio/transcript review.
6. Execute the archive migration only after backup, path manifest, dry-run diff, and owner review.
7. Run one low-cost canary per provider, then freeze representative API fixtures for adapter tests.
